# Solver

> Summary: Whether a level can be cleared without boosters, proven by searching every arrangement of its blocks the player can reach, with the fewest moves when it can: `Solvable` with a solution to play back, `Unsolvable` when no arrangement leads every block out, `Unknown` when the caller stops the search first (a state budget, a time limit or a cancel). Plain C# in `Game.Logic`, using the board's own rules.

## Code
- Folder: `Assets/Game/Logic/Levels/Solving/`
- Assembly: `Game.Logic`
- Entry points: `LevelSolver.Solve(level, keepSearching)` (`Logic/Levels/Solving/LevelSolver.cs`), where `keepSearching` gets the number of arrangements searched after every place tried and stops the search by returning false, and `LevelSolver.Solve(level, stateBudget)` for a plain budget; both return a `LevelSolution` (`Verdict`, `Moves`, `Rearrangements`, `ExploredStates`); `Solvability` and `SolutionMove` are its result types. `BlockReach` (where one block can go in one drag), `InterchangeableBlocks` and `ArrangementKey` (which arrangements are the same) and `BoardArrangement` (`Logic/Play/Board/`, a snapshot of the board's blocks) are internal to `Game.Logic`.

## How it works
- **A move is one drag.** The finger can lead a block along any path through free cells (the drag steps around obstacles, [Board](Board.md)), so one move takes a block to any place it can reach by free steps. `BlockReach.Find(board, block)` walks those places on the board itself, a breadth-first fill that places the block on each (`Board.Place`) and asks the board's `CanStep` in every direction and `CanLeave` at every place. It stops at the first place the block can leave from (`CanLeave`, `ExitPlace`); otherwise `Places` holds every other place it reaches. It puts the block back where it stood. The rules come from `LevelMechanics.For(level)`, so ice and arrows apply as in the game.
- **Leaving is never wrong.** A block that leaves only frees cells and melts ice; no rule gets stricter with fewer blocks, so whatever the other blocks could do before they can still do after. So the solver lets every block that can reach a door leave as soon as it can (`LeaveAll`, repeated until none can, since one leaving can free or melt another), and searches only the arrangements where no block can leave. Every block leaves exactly once, so a solution has one move per block plus its rearrangements, and leaving early never costs one.
- **A block that fits no door.** A block with no door of its color it can pass through (`BlocksCanLeaveCheck.EveryBlockFitsADoor`, the validator's warning: wide enough, and allowed by its arrow) can never leave, so such a level is `Unsolvable` at once, with no arrangement searched. A level being drawn, blocks before doors, is usually one, and would otherwise be the longest search.
- **The search.** Breadth-first over arrangements, counting rearrangements: from each settled arrangement, every block to every place it reaches, then every block that can leave leaves. An arrangement already seen is skipped, so the cost is the number of different arrangements, not the number of move sequences. The board is set to each arrangement with `Board.Arrange` before a block is moved.
- **Alike blocks are one.** Two blocks of the same color, shape, ice and arrow behave the same anywhere, so an arrangement and the one with the two swapped are the same arrangement: `InterchangeableBlocks` groups such blocks and `ArrangementKey` writes each block's position (or gone) with the positions inside a group sorted. With three alike blocks this searches a sixth of the arrangements. A test fails when `BlockData` or `ArrowData` gains a field, so a new block property cannot be left out of the comparison.
- **The block just moved stays.** After a rearrangement only the other blocks are asked whether they can now leave: the moved block reaches the same places from its new place as from its old one, none of them by a door, since it could not leave before. Once any block leaves, every block is asked again, as ice may have melted.
- **Verdicts.** The first arrangement with every block gone ends the search with the fewest rearrangements, since breadth-first finds shallower arrangements first; the moves are read back through each arrangement's parent. No arrangement left to search means `Unsolvable`: every arrangement reachable from the start has been tried. `keepSearching` returning false first means `Unknown`: neither proven.
- **The solution.** `SolutionMove` is a block (its index in the level), the place it goes to and whether it leaves from there. Replayed in order with `Board.Place` and `TryLeave`, the moves clear the board.

## Rules & invariants
- `Unsolvable` is a proof, for the board's rules without boosters: a hammer or rocket can still clear such a level. `Unknown` is never shown as unsolvable.
- The time limit plays no part: the verdict and the move count say nothing about seconds.
- The level must have no errors from `LevelValidator` (no overlapping blocks or cells off the board); the solver works on what the board builds from it.
- The board's blocks are the level's, one for one: a solver board is never split or hit, so `Board.Arrange` and `BoardArrangement` hold one entry per level block and ice depends only on the blocks gone.
- Every step can be taken back: wherever a move rule lets a block step one way, it lets it step back (occupancy is the same both ways, an arrow allows both ways along its axis, ice holds a block in every direction or none). The moved block's shortcut rests on this. A new `IMoveRule` that allows a step but not the step back (a one-way tile) must drop that shortcut, asking every block again after a move.
- The case's five levels need at most one rearrangement and 20 arrangements (`Level_05`); levels 1 to 3 are cleared by leaving blocks alone, in one arrangement.
- No heuristic ordering: on the case's boards every arrangement is searched in milliseconds, and a heuristic does not help prove a level unsolvable, which takes every arrangement either way ([Decisions](../Decisions.md)).
- Crowded boards have few arrangements and are decided at once. A large, open board has many: each block can stand almost anywhere, so the arrangements grow with the free places to the power of the blocks, and proving such a level unsolvable can take minutes. That is why the editor's check after every change is limited in time and the full search is a button with a cancel ([Level editor](LevelEditor.md)).
- The solver allocates freely (one snapshot per arrangement); it runs in the editor and in tests, never per frame.

## Tests
- `Tests/Levels/Solving/LevelSolverTests`: a block that reaches its door in one move; a block in the way that can leave leaves first with no rearrangement; a column where no block can leave at the start takes exactly as many rearrangements as blocks in the way (1, 2, 3): the blocks in the way can leave only after an iced block beside the column melts, which needs the column's block out first, so each must be moved aside once; the solution replayed on the board, each rearrangement to a reachable place, clears it; two blocks that cannot pass each other are unsolvable after exactly three arrangements; a block that fits no door is unsolvable with none searched; a budget too small gives `Unknown`; ice that melts when another block leaves orders the exits, ice that never melts is unsolvable; an arrow across the way to the door decides whether the block can leave; a move that opens the way of a distant block lets that block leave at once.
- `Tests/Levels/Solving/LevelSolverEquivalenceTests`: on 150 random small levels (fixed seed) the solver agrees with `ReferenceSolver`, a search with none of the solver's shortcuts (no leaving at once, no alike blocks, every block asked after every move, a block that could leave also moved to every other place it reaches, leaving as one more move at no cost; its own reach fill, as `BlockReach` stops at the first exit), on the verdict and the fewest rearrangements wherever both decide.
- `Tests/Levels/Solving/ArrangementKeyTests`: alike blocks swapped give equal keys with the same hash, different blocks swapped or a block moved or gone do not, blocks differing in color, shape, ice or arrow are not alike, and the field lists of `BlockData` and `ArrowData` are the ones compared.
- `Tests/Levels/Solving/BlockReachTests`: every other place on an empty board, nothing past another block or for an iced block, the place touching its door, the block put back where it stood.
- `Tests/Play/Board/BoardArrangementTests`: `Arrange` restores positions and blocks gone with their cells and counts, `Place` moves a block's cells, `CanLeave` changes nothing.
- `Tests/Levels/ProjectLevelsTests.EveryLevelAsset_IsSolvable`: every level asset is solvable within the full check budget of the project's `SolverSettings` asset, the editor's; it writes each level's moves, rearrangements and arrangements searched to the test output.

## Editor
The level editor solves every level without errors after each change for a moment and fully on request, shows the verdict, plays the solution back and asks before saving an unsolvable level ([Level editor](LevelEditor.md)).
